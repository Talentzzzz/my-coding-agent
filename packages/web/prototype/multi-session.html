这个原型在回答什么

  1. 输入框与模型座位属于谁：每一栏各有一套（都画在窗格内），另外每套都钉一个"发送到 ⟨本栏会话⟩"标签——所以"跟随会话"这件事是被画出来的，不是靠焦点推断的；反过来，这也让"一个窗口一条输入框"成了一个还没被否掉的候选。
  2. 侧边栏那一行：多会话活着时，它显示会话标题 + 一行状态（运行中 / 待审批 / 失败 / 已打开 · 空闲 / 无标记）。
  3. 未聚焦还在跑：并排时未聚焦那栏的标题条变暗但不隐藏，状态徽章照旧可见；侧边栏那一行也有琥珀色点 + 文字；多标签形态则由标签条承担。
  4. 审批横幅：画在它自己那一栏里。并排的初始画面就是"聚焦右栏（在跑）、左栏停在审批上"，所以它不是聚焦的那一栏。
  5. 状态行：每栏一条（每栏说的是自己那个会话的数）。

换一个形态试试

  1. "单会话"= 今天的基线：标签条与"窄栏"处理都消失、每栏只剩一栏，但侧边栏那行状态与输入框的目标标签不会消失——它们是这次提案里唯一进了基线的两样东西，正好拿来判断"值不值"。
  2. "窗口内多标签"= 一个会话占满右半列，标签条负责"谁在跑"，未聚焦窗格整栏隐藏。
  3. "并排两栏"= 右栏聚焦且在跑，左栏停在审批上（横幅在左栏）。

我不确定的地方

  1. 一行状态够不够？五个会话里三个在动，侧边栏会不会变成一片琥珀色。
  2. 输入框跟随焦点，会不会发错会话——"发送到"这个标签是补丁还是必需。
  3. 并排只有两栏时，第三个在跑的会话在并排画面里没有任何记号（并排不画标签条），只剩侧边栏一个信号，够不够。
  4. 每栏一条状态行，两栏并排时这两条数字会不会互相打岔。
  5. 审批横幅留在自己那一栏，是否会让人找不到——还是必须做一个"跳过去"的入口。
