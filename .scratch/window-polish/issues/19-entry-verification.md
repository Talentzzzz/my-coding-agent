## Answer

### 结论

**三个入口在最新构建里全部可达且可用**，没有一个是「点了没反应」。`npm run check` 先绿
（token 审计 127 定义 / 101 引用）→ `npm run build:web` 刷新 `packages/web/dist` → 真窗口核验
**24 条断言全绿、退出码 0**（连跑三次都是 24 / 0 / 0）。用户报的「没实现」因此不是功能缺失，
是**旧构建 + 入口藏得深**这两件事叠加，见末尾。

### 怎么跑的

`.scratch/window-polish/research/verify-19.ts`（09 号那套：`bootServer` + 脚本传输 + 本机
Chromium、**生产 bundle**、真浏览器，三个入口全部**在真 UI 上点**，一步没走 dispatch 绕过）：

```bash
npm run build:web && node .scratch/window-polish/research/verify-19.ts
```

全程走真 UI：在输入框发消息造出会话 → 右键会话行 → 就地改名并回车 → 右键派生 → 右键删除 →
点回源会话行 → 右键用户消息「从此分支」→ 再发一句岔出第二条走法 → 点固定头「当前分支」进分支页
→ 选另一条走法 → 按按钮切回去。完整断言输出留在 `research/verify-19-output.txt`（那是一次**留档
运行**的原始 stdout，里面的 `!!` 行是过程记录、不是断言失败）。

harness 自己踩了两个坑，都不是入口的问题，已就地修掉并留在注释里：① 左栏清单是**整机**的，
按固定开场白找会话行会撞上上一次运行残留的同名临时工作区（于是操作落到旧会话上），现在每次运行
带一个唯一短标记；② 常驻通道接上之前按下的第一句会被丢掉，现在先等
`.channel-indicator[data-state=live]` 与清单帧，再以「输入框有没有被清空」确认发送落地。

### 执行期发现（另开票，没在本票里修）

核验跑出**两条真 bug**，都按第 2 条办：现象与最小复现留在各自的票里，本票不顺手修。

1. [21 删掉刚派生的会话后，窗口给这个已经没了的会话补发一次 `open`](21-fork-then-delete-stale-open.md)
   ——**先派生、再马上删掉派生行**，右栏底部挂出红横幅「未知的会话：&lt;刚被删掉的那个 id&gt;」。
   `openSession` 在两次 await 之后才 `mux.retain`，而 `aria-current` 在那之前就挪过去了，于是
   用户能在一个「看起来已经就位」的行上删掉它，`deleteSession` 的 `release` 成了空操作，续段
   再把 `open` 补出去。复现脚本 `research/repro-19.ts`（三步：派生 → 等 `aria-current` 挪过去就删
   → 点回源行）、图 `research/repro-19-banner.png`。**核验流程每次都会撞上它**：连跑三次，留档的
   `verify-19-output.txt` 里就是一条 `!!  错误横幅 @B1`，另两次同样各一条——它出现的位置随
   「派生」到「删除」之间隔了多久而变（也见过在 A5 就冒出来）。**三个入口本身全绿，红字是这条
   竞态白送的噪音**；核验脚本对它只记不断言（记完在结尾数一次），所以那一行不影响退出码。
2. [22 空态里的模型位读作「（已丢失）」](22-empty-state-model-seat.md)——删掉正在读的会话、窗口
   回到空态后，输入框右下写着「（已丢失）」而名字是空的（`v19-a5-deleted.png`）：`model === ""`
   这个「还没轮到选」的第三态被 `composer.ts` 当成了「选过、但那一行没了」。

### 用户那句「没实现」的核对结论

代码在最新构建里是好的，用户看不到最可能是这两条（map 里 10-15 那条核实结论继续成立）：

- **跑的是旧构建的窗口**。桌面外壳服务的是 `packages/web/dist`——改完必须 `npm run build:web`
  （或 `desktop:dev`），**而且已经开着的窗口要重开**。本票把 `dist` 重新构建过了。
- **入口本来就藏得深，两处都藏在「要有前提」后面**：fork / 改名 / 删除**只**在会话行的右键菜单
  里，行上没有任何常驻按钮、hover 也不出现；分支入口的「当前分支」块在**只有一条走法时整块
  隐藏**（09 号拍板），**得先分过一次岔**才出现，而进分支页的第二条路（用户消息右键「查看
  分支图」）同样只在右键菜单里。这两条都是既定设计，本票没有改动，原样保留。
