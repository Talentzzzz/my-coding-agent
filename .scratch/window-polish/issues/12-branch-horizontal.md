# 12 原型第四轮：顶部固定、树横过来、缩放、选中再回去

Type: prototype
Status: resolved
Blocked by: 01

## Question

用户看过第三版原型（01 的 ③）之后，对**分支页**和**会话顶部**提了四条：

> 首先，会话顶部是固定的，也就是调整会话内容宽度不会影响会话顶部 …… 看这个图片的会话和顶部；而且我希望
> 树是从左到右的，左侧是根，并且 分支 页里可以随意放大，然后可以选中当前分支，也就是一个节点，
> 然后点击一个按钮，就回到对话，同时对话里要显示当前分支，你接着做原型我看看

随话给了一张**参考实现的窗口截图**（页签「对话 / 分支」钉在会话列左上角、正文在它下面居中收窄），
并在页签旁手写「我们的成就：对话 分支」—— 指的是"顶部这条不跟着正文宽度动"这件事。

要定的是四件：① 顶部与正文宽度的关系；② 树的方向；③ 分支页的缩放；④ 选中与"回到对话"的流程，
以及"对话里显示当前分支"画在哪。**原型放在 `../prototype/index.html`，改完跑
`node .scratch/window-polish/prototype/shoot.mjs` 出图并核对。**

## Answer

四条都落进原型了，改动集中在 `prototype/index.html` 的固定头、分支视图两处（`shoot.mjs` 跟着改，
出图在 `../research/`）。**这一轮推翻了 01 的 ③ 的几何与交互两半，也改写了 09 的三条。**

1. **会话顶部是整列的一条固定头。** 页签、「当前分支」抬头、以及分支页那行工具**钉在会话列的左右
   两端**（`padding-inline: 24px`，整列宽），不再放在居中的 `.reading` 里 —— 所以推阅读列把手，
   页签一动不动（实测 `x 311 → 311`，头部宽 `840 =` 会话列宽）。正文与输入框仍然居中、宽度仍归
   阅读列把手管。**这就是参考实现的做法**（那张截图里页签在列左缘、正文在下面居中）。反过来那条
   路（把阅读列改成左对齐，顶部与正文就永远对齐）**留给 04 一起拍**。
2. **树从左到右长，根在最左那一列。** 上一版是"从上往下铺泳道"，现在把 x / y 换了个位：
   **列 = 深度，行 = 泳道**。几何与上一版同构，所以 09 里"别自己另发明一套"那句仍然成立 ——
   主干占**最上面**那一行（于是它是一条水平直线）、换行处拐一个肘、行序深度优先，规则一条没变。
   一个节点是一张两行的卡：上一行是这条走法的摘要（用户那句话），下一行是**短 id + 轮次**
   （真实现里短 id 就是 entry id 的前几位，所以这一列不是装饰）。实测 x 递增
   `root 311 < v0 576 < v0b 841`，兄弟同列，主干 `root.y = v1.y`。
3. **分支页可以随便缩放，也能平移。** `−` / `＋`（每次 ×1.2，范围 40%–300%）、`适应`（缩到刚好
   装下）、`Ctrl / ⌘ + 滚轮`（按指针位置缩放，指针指着的那一点钉在原地）、空白处拖着平移。
   进分支页时**自动选一个"装得下就 100%、装不下才缩"的默认比例**（本机 840px 的列 → 88%，
   一打开就看得见整棵树）。实现上图的自然尺寸与缩放后的尺寸是两回事：外面那个 `graph-sizer`
   撑出真正的滚动范围，里面 `graph-zoom` 才是 `transform: scale()`，所以文字是矢量放大的、不糊。
4. **点节点只"选中"，按按钮才真的走。** 这是这一轮**最实的一处推翻**：01 的 ③ 写的是"点任意一行
   切过去"，现在改成两拍 —— 点一下 = 选中（蓝圈 + 卡片上「已选中」），固定头右边的按钮从「回到对话」
   变成主按钮「**切到这一条并回到对话**」，按下去才换记录并回到对话页。**连点两下等于「就它了」**
   （省一次点击，不改语义）。选中项与它落在第几轮，写在固定头左边那行提示里。
5. **对话页也显示当前分支。** 固定头右边一条抬头：`当前分支 <短 id> <这条走法的摘要>`，点它直接
   去分支页 —— 切走切回、缩放、跳到别的正文，它一直都在。只有一条走法时**抬头与页签一起收掉**
   （09 的"至少两条走法才有意义"照旧）。
6. **一处顺手补的**：原型的四条走法只有两荤两素，看不出"深一层"的样子，所以树的第三个节点
   （`v0b`）留在原型里当第二层。它验证了"深度 = 列"这条排布真的会往右长，而不是我嘴上说的。

数字留在 `shoot.mjs` 的输出里（都是绿的、`no page errors`）：5 节点 / 4 条连线 / 5 个圆点、
进页面 88%、放大三次 153%、`适应` 88%（图宽 = 视口 840）、空白处拖动 `scrollLeft 438`、
选中 v0b 之后"对话没动"、按按钮后末条用户消息换成 v0b 那句、抬头跟着换成 `9ceeb5d`。
上一轮那些（左栏改名 / fork、两个把手、状态行三字段、fork 行与普通行同形）逐条复跑，没被改坏。

**留缺口（都是这一票故意没做的）**：切分支在原型里仍然只换第 2 轮的正文，真实现要动会话的 `leaf`
与整段记录（09 的 ⑤）；根节点不可选（它是共同祖先，不是一条走法），所以图里它是灰的；缩放比例
不持久化（跟宽度一样，是 04 的"记不记得住"）；树铺到十几条走法时要不要折叠、要不要给一条路一个
名字，仍然是 09 的 Not yet specified。
