# 09 分支：会话顶部一个入口，整个会话区换成一张树

Type: task
Status: resolved
Blocked by: 01, 02

## Question

把「分支」从**每条消息上的按钮**变成**会话顶部的一个入口**，点开之后**整个会话区换成一张树**。
（01 的 ③ / ⑫：这一条被用户推翻过两次才落到第三版；**13 号又把"两个页签"拆成了一个入口**，
所以标题里那个"页签"现在读作"固定头右上角那一块"。）

> **动手前先读 [12 号](12-branch-horizontal.md) 与 [13 号](13-branch-focus.md)（两张原型票改的
> 都是这一票）**：① 树是**从左到右**的（列 = 深度、行 = 泳道，**根在最左那一列**），不是从上往下（12）；
> ② **「对话 / 分支」两个页签没有了** —— 固定头最上面一行是**会话标题**，右边那一块「当前分支」是
> **唯一**的入口，分支页里那个按钮是唯一的出口（13）；③ **点一个节点只是选中**，按那个按钮才切过去
> 并回到对话（12）；④ 分支页 **Ctrl+滚轮缩放、按住左键拖画面**（13；`−`/`＋`/`适应` 留着当兜底）；
> ⑤ **分支页里没有输入框**（13 把 01 的 ⑫ 推翻了）。下面第 1、2、5、6 条已按此改写。

要做的：

1. **入口就是固定头右上角那一块「当前分支」**（13 号拆掉了 12 号那两个页签）。它在会话列最上面一条
   **整列宽的固定头**里，右边只有它一个：分叉图标 + `当前分支` + 短 id + 这条走法开头那句话。
   点它 = **记录整块被替换掉**（不是浮层、不是侧栏）；回来按分支页里那个按钮——那是唯一的出口。
   **它什么时候出现**：一条路的时候「分支」没有意义，所以**至少两条走法时**才渲染这一块（13 号做的
   是整块 `hidden`）。状态跟着会话走（切换会话 / 切分支都要重算）。同一行的左边是**会话标题**
   （服务端派生出来的那个），标题与入口都不跟着阅读列宽度动（12 号那条）。
2. **图的画法照 git，但方向是横的**（12 号改）：**列 = 深度（往右长）、行 = 泳道，根在最左**。
   一条走法占一行，分支点上拐一个肘换到另一行，节点是线上的圆点 + 一张两行的卡
   （上一行是这条走法的摘要，下一行是短 id 与轮次）—— **主干永远占最上面那一行**，所以你现在读的
   那条从头到尾是一条**水平直线**。短 id 真实现里就是 **entry id 的前几位**，因此它不是装饰。
   原型的实现在 `../prototype/index.html` 的 `layoutGraph()` / `paintGraph()`：
   排位置的规则只有一条（主干上的孩子接着父行，其余各开一行新的），行序深度优先；肘是
   "直着出一小段 → 拐 → 竖过去 → 拐 → 直着进"。**照抄这套几何与这套尺度（300 / 58 / 268×46），
   别自己另发明一套**，也别把上一版的纵向版本搬回来。**缩放与平移的装置**（`graph-sizer` 撑滚动 +
   `graph-zoom` 做 `transform: scale()`）一起照抄：进页面时"装得下就 100%、装不下才缩"。
3. **拆掉内联控件**：`turn-actions` 整块（`从此分支` + `派生新会话` + `‹1/1›`）从每条消息上消失。
   分支的入口只留两处：用户消息的右键菜单，和顶部那个页签。
4. **数据要自己聚一次**：今天 `item.branch.options`（`BranchOption[]`）是**挂在那一条消息的
   item 上**的，只回答"这个分支点有哪几条走法"。要画整张图，就要沿 `items` 把**所有**
   `branch?.options.length >= 2` 的 item 收起来，按出现顺序串成树 —— 一个分支点一个节点，
   它的 `options` 是它的子节点，`option.active` 决定主干。**这条要在 `state.ts` 里聚成一份快照
   字段**，不要让视图每帧去扫 `items`（`transcript` 是热路径，前一个 effort 的 03 号已经把这条
   教训写死了）。**并且要和行模型对齐**：现在一个节点 = 一条消息 item，要不要把工具步骤也铺进去、
   要不要把分支点自己也算一行，先定下来再写。
5. **切换要真的换记录，而且是两拍的**（12 号改）：点一个节点 = **只选中**（蓝圈 +「已选中」），
   按固定头右边那个按钮 = 移动会话的 `leaf`、重新基线整段 transcript、**并回到对话页**
   （`main.ts` 里那条切 branch 的路径已经在跑）；按钮的措辞跟着走（没换目标时是「回到对话」，
   选了别的走法时变成「切到这一条并回到对话」）。**连点两下 = 直接切过去**，这条保留。
   对话页的固定头**一直显示当前分支**（`当前分支 <短 id> <摘要>`，点它回分支页），只有一条走法时
   抬头与页签一起收掉。**原型的"只换第 2 轮正文"是假动作，别照抄。**
6. **分支页里没有输入框**（13 号推翻了 01 的 ⑫）：底部的对话框**整块收掉** —— 连工作目录那一行与
   状态行一起，这一页只有那棵树、摘要行和固定头里那行工具。所以"输入框顶上那个工作目录芯片在分支页
   也会在"这个顾虑不存在了。要往另一条路上说点什么，先按那个按钮回对话页。

`npm run check` + `scripts/smoke-stream.ts` / `smoke-sidebar.ts` 要绿。**答案里要看图**：
分支图、切到另一条之后、以及只有一条走法时页签不出现的样子，各一张，放进 `../research/`。

## Answer

六条都落进了 `packages/web`，`npm run check` 与 `smoke-stream` / `smoke-sidebar` / `smoke-mux-client`
全绿。出图在 `../research/`（`shots.ts`：bootServer + 假传输 + 本机 Chromium，**对话全程走真 UI**
——输入框发消息、右键菜单 rewind、分支页点选、按钮切换）：
[分支图](shot-branch-graph.png)、[选中另一条](shot-branch-selected.png)、
[切过去之后](shot-branch-switched.png)、[只有一条走法](shot-branch-single.png)。

1. **入口就是固定头右上角那一块**（`main.ts` 的 `branchChip`）：分叉图标 + `当前分支` + 短 id +
   这条走法开头那句话，点它进分支页。固定头重排成两行（`header-row` + 分支页的工具行），整列宽、
   `padding: 0 24px`，不跟阅读列走。**出现时机**：`state.branchTree` 存在才渲染（一个分支点都没有
   时整块 `hidden`），随每条 baseline 重算，所以切会话、切分支都跟着走。只有一条走法时那一行就
   只剩会话标题（`shot-branch-single.png`）——「当前分支」这个说法在那时确实不成立，收掉是对的。
2. **图照抄原型的几何与尺度**（`render/branch-view.ts`）：列 = 深度、行 = 泳道、根在最左，`300 / 58 /
   268×46`，规则一条 —— 主干上的孩子接着父行、其余各开一行新的、行序深度优先、path 上的孩子排最前
   （所以当前走法是最上面那条水平直线）；肘是「直出一小段 → 拐 → 竖过去 → 拐 → 直进」；
   `graph-sizer` 撑滚动 + `graph-zoom` 做 `transform: scale()`，进页面「装得下就 100%、装不下才缩」。
   实现用 `createElementNS` 逐个建节点（不拼 innerHTML），泳道四色读自 token（`--dsw-lane-1..4`，
   新增一枚 `--dsw-static-purple-400`），短 id 就是 **entry id 的前 7 位**。
3. **内联控件拆干净**：`turn-actions`（从此分支 / 派生新会话 / `‹1/1›`）与它们的样式整块删除；
   transcript 只留下一个 `contextmenu` 监听，把「哪条用户消息、哪个 entry、指针在哪」交给 `main.ts`。
   入口两处：用户消息右键菜单（「从此分支」= rewind 到那条消息，留在对话页等下一条消息；
   「查看分支图」= 进分支页），和顶部那块 chip。**顺手修了 menu.ts 一个真 bug**：
   `onOutside` 挂在 document 的捕获相上，跑在菜单自己的 `stopPropagation` 之前——真浏览器里
   **任何菜单项都点不中**（pointerdown 一到菜单就先被拆了，click 落空）。smoke 是直接 dispatch
   handler 的，所以一直没暴露；修法是 onOutside 先看指针是否落在打开的菜单里。
4. **聚合在 `state.ts`，一次 baseline 折一份**：`buildBranchTree(snapshot)` 产出
   `{ rootLabel, ways, currentId, points, options }`，挂在 `ViewState.branchTree` 上；视图与 chip 都读
   这一份，没有任何每帧扫 `items` 的路。数据源直接用 `snapshot.branchPoints`——它与「沿 items 收」
   等价（`attachBranches` 本来就是按 entry id 一对一配对），于是 `item.branch` 字段与
   `attachBranches` 整个删掉了。**行模型的对齐这样定**：一个节点 = **一条走法**（一个 option，卡片
   念的是它下面第一句话，`label` 服务端已给），工具步骤**不铺进去**，分支点自己**不算一行**——根
   卡代表共同祖先（念会话标题），灰的、不可选。「轮次」= 到分支点那句话为止的用户消息数，走法的
   第一句自己是 user 就再 +1。串树的规则：链按顺序来，后一个分支点的 options 挂在前一个分支点的
   **active** option 下面（链离开一个分支点只会走它标 active 的那个孩子），最深处的 active option
   就是「现在读的这条」。
5. **切换是真的换记录，两拍**：点节点只选中（蓝圈 + 「已选中」，`select()` 只重画图），固定头工具行
   的按钮没换目标时是「回到对话」，选了别的走法变主按钮「切到这一条并回到对话」——按下去
   `POST /branch { entryId, descend: true }`（真移 leaf，应答快照直接 apply，channel 的
   `branch_changed` 基线随后也到）。**连点两下 = 直接切过去**（dblclick = 选中 + 应用）。运行中
   流式时按钮禁用（循环正在往树上写）。原型那个「只换第 2 轮正文」的假动作没有照抄。
6. **分支页没有输入框**：`body[data-pane="branch"]` 一条 CSS 把 transcript、banners、composer-wrap
   （连同工作目录芯片与审批卡）和状态行整块收掉，分支视图顶进 transcript 那个 `1fr` 网格行；回到
   对话页一切原样回来（transcript 的 DOM 一直在，只是 `display:none`）。工具行（选中提示 +
   `−`/`100%`/`＋`/`适应` + 出口按钮）钉在固定头第二行，滚图跑不掉；Ctrl+滚轮按指针锚定缩放、
   按住左键拖画面（4px 位移分家「点」与「拖」），提示写在摘要行里。

**看真数据时定下来的两件事**：服务端只报**活跃链上**的分支点（`getBranchPoints` 走的是 chain），
所以** inactive 走法自己的子分支不在图里**——树是「当前视角的树」，切到某条路上，它自己的岔才会
长出来（12 号留的「树很大怎么办」因此先不折不叠，等这条缺口真硌到人再开票）。「摘要行 + 手势提示 +
三个缩放按钮」照 13 号留的兜底全保留。

**过程里顺带证实的两条既有事实**（都不是本票引入的）：只看不动的窗格在宿主退场后停在旧基线
（pane 不拿 claim，流结束了不会自己重开；窗口自己的动作——发送重开流、branch 的应答自带快照——
会把它带回当下，出图脚本因此全程走真 UI）；本机全局会话清单堆了几百个历史 smoke 工作区，
工作区菜单现在有一百多行且不可滚动（`openMenuAt` 有视口钳制但菜单本身没有 max-height）——
环境与 08 号的活，另说。
