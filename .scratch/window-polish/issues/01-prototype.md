# 01 交互原型：两个右键入口与观感

Type: prototype
Status: resolved

## Question

把这一轮要的四件事先做成**能点的东西**，好在讨论观感时对着它说话，而不是对着形容词说话：

1. 左栏一个会话行**右键** → 菜单里有「派生新会话」→ 左栏出现 `原标题（1）`，挂在源行下面。
2. 会话里**用户消息右键** → 菜单里有「分支」→ 左栏不变，会话**顶部**多出一条分支条。
3. 左栏宽度可拖、阅读列宽度可拖。
4. 排版：去 logo、字号与行高、每轮一个圆点、用户消息下的分隔线、工具行读作
   **一行 `Name  path`**（点开才展开内容）、输入框里的模型选择器挪到**右边**、去掉那两行提示字。

原型放 `../prototype/`，自包含（不引外部依赖），浅深两套皮肤可切换。**原型里的尺寸就是在投票**：
它定下来的字号阶、行高、间距，05 / 06 / 07 三票照它落地。回答要写清"哪几条定下来了、哪几条只是
一个取向、哪几条还等你拍"，并把下面四处写成**明确的、可以被推翻的**选择：

- 右键菜单是自绘还是借原生 `contextmenu`；
- `（1）` 这个后缀由谁算（客户端还是服务端），序号按什么排序；
- 分支条长什么样、放在会话顶部哪一行的位置、各消息上还要不要留 `‹1/1›`；
- 工具行展开后显示什么（原始 stdout、diff、还是"归档"提示）。

## Answer

> **③ 与 ⑫ 后来又被改过两轮**：[12 号](12-branch-horizontal.md) 把树转了九十度（从"从上往下铺泳道"
> 改成"从左到右、根在最左"）并把"点一行切过去"改成"选中 → 按按钮 → 带着它回对话"；
> [13 号](13-branch-focus.md) 把"两个页签"拆成"固定头右上角一个入口"，并把 ⑫ 里"输入框留着"那条
> 落地成"分支页里没有输入框"。**下面这两条按当时的版本读。**

原型落在 `../prototype/`：`index.html`（一页可切换「整窗 / 左栏 / 会话」三视图的整窗原型，带主题开关
与可开关的标注气泡）、`typography.html`（"现状 vs 提案"的字号与观感对照，左边逐条抄了 `style.css` 的
真值）。两个都自包含、浅深两套。四条拍板：

1. **右键菜单自绘，不借原生。** 原生的 `contextmenu` 在 Electron 里会走系统菜单的外观，和窗口里
   其余所有浮层（工作目录菜单、设置面板）不是一套东西；自绘还能把快捷键、图标、分隔线一起带上。
   会话行**不再常驻任何按钮**——连 hover 也不出现（参考实现的 hover 操作区是给"重命名/归档"这类
   高频动作的，而这里的入口只有 fork 与删除，藏在右键里反而更安静）。
2. **`（1）` 是纯显示，且由左栏在渲染时拼。** 这条被 02 号改了：会话文件里**根本没有标题字段**
   （`SessionHeader` 没有 `title`），标题永远是从分支首条 user 消息派生的（
   `session-manager.ts:767-786` 的 `titleOfBranch`），而 `entryId = null` 复制的是**整份日志**，
   所以**所有 fork 的服务端标题都等于源标题**。于是"客户端算一个带 `（1）` 的标题"这条路是假的——
   它会被服务端随后下发的 `session_row` 覆盖（`mux.ts:576-578`）、重开就没了。
   **正确的做法是根本不存这个后缀**：源标题原样来自服务端，`（N）` 由左栏在**渲染行**的时候拼——
   N 就是它在**同一个父行下的兄弟序号**（按创建时间排）。这样跨窗口一致、重开一致、零存储，
   连派生三次得到 `标题（1）（2）（3）`，派生出来的再派生得到 `标题（1）（1）`（后缀挂在父行的**显示**
   标题上）。**这条决定了 08 号里"（1）"属于左栏的渲染，不属于 fork 那一刻。**
3. **分支做成"会话顶部的两个页签 + 一整个 git 泳道图"**（**第三轮反馈推翻了前两版**）。
   演化是：初版 `‹ 2/3 ›` 的一条窄条 → 第二版"窄条 + 弹层里一棵缩进树" → 现在这一版：
   会话最上面两个页签**「对话 / 分支」**，选「分支」之后**整个会话区就全是分支**（不是弹层、
   不是侧栏），里面画的是一张 **git 那种泳道图** —— 一条泳道走一条路，分支点上拐一个肘出到新泳道，
   节点是圆点，**实心点连起来的那条直线就是你正在读的那条路**，点任意一行切过去。
   **排泳道的规则只有一条**：主干永远占最左那条泳道，所以它从头到尾是一条直线；每个分支点上，
   在主干上的那个孩子接着父泳道，其余各开一条新的；行序深度优先，一棵子树画完才轮到它右边的兄弟。
   **数据上它本来就成立**：每一层就是某条消息 item 的 `branch.options`，沿着 `items` 把
   `options.length >= 2` 的都收起来就是这棵树，不需要新的服务端事实。各消息上不再有 `‹1/1›`。
   行里还带一个短 id（`9f21c0a` 这种）—— 真实现里那就是 entry id 的前几位，所以这一列不是装饰。
4. **工具过程读作一行。** `Read  README.md`、`Bash  npm run check`、`Edit  src/main.ts  +12 −3`——
   名字在前、路径在后、弱化描色，整行点开才展开内容（等宽、可滚动）。正文里的 `[调用 read]`
   占位文本从 `state.ts` 拿掉：正文只留模型自己说的话。
5. **会话行收成一行。** 现状是"标题 + 第二行状态"（"● 运行中" / "▍ 已打开 · 空闲"），
   第二行还要 `min-height` 兜着防止跳动。改成**只有一行 32px**：运行中 / 待审批收进左边那个
   16px 的槽（一个琥珀色圆点），"已打开"就是 `aria-current` 那条底色本身——它本来就不该多写一行。
   这直接省掉 `COLLAPSED_COUNT` 那一套里"第二行让每行更高"的顾虑，也让参考实现的 32px 行高成立。

**第二轮反馈又改了六条（都是用户看过第一版之后提的）：**

6. **不再有"每一轮一个点"。** 初版给助手每一轮左边画一个圆点（用来顶替"智能体"那一行），用户
   直接说"去掉"。所以**轮与轮之间没有任何标记**：用户消息一条、下面一条细分隔线，然后就是内容。
   "智能体"那一行和那个点一起没了，会话里只剩内容和分隔线。
7. **工作目录属于输入框，不属于会话。** 初版把它摆在会话左上角，用户说"应该在输入框顶部的最左边"。
   于是它现在是输入框卡片**上方那一行**的最左边（`POST /api/sessions` 的 cwd 与"新会话落在哪个
   工作区"三处同源的语义没变，变的只是它画在哪）。
8. **fork 出来的会话跟普通会话长得一模一样。** 初版给它缩进 + 一个 ▸ 标记，用户说"就是多了个（1）
   而已"。现在它不缩进、槽里什么都不画，**只有名字带上 `（1）`**；它仍然紧跟在源会话下面 ——
   位置就是"它从哪儿来"，不需要再画第二遍。
9. **改名是真的能改。** 会话行的右键菜单里「重命名」就地变成一个输入框，Enter 提交、Escape 取消。
   编辑的是**去掉后缀的那个名字**，后缀自己会拼回来（它是派生的事实，不该让用户敲进去）。
   **这条把一个新问题顶出来了：标题现在是"从分支首条 user 消息派生"的，没有存储，所以改名存不下来**
   —— 单开 11 号。
10. **阅读列把手的方向反了。** 初版抓左缘往右推是变宽，用户说"方向弄反了"。现在往右推是变窄
    （阅读列居中，所以位移乘 -2，把手仍然跟得住指针）。
11. **状态行不加东西。** 初版在右边多加了一句"1 轮 6 步"，用户说"不用显示几轮几步，还跟以前一样
    三个字段即可"。现在只有 `total` / `cache` / `context`。

**第三轮反馈只改了一条（⑫），但它把 ③ 整个换掉了：**

12. **「分支」是一个页签，不是一条常驻的条，也不是弹层。** 用户的原话是"你可以在顶部划分两个选项，
    对话 分支，当用户选分支后，整个会话里就全是分支，而且分支树你可以参考 git 的样式"。
    所以：页签在会话最上面（和参考实现的「对话 / 轨迹」同一位置），选「分支」时**记录整块被替换掉**，
    不是浮在上面；图的画法照 git —— 泳道 + 肘 + 圆点 + 短 id。
    **一处我自己定的、可以被推翻**：输入框在「分支」页签里**留着**（参考实现的「轨迹」也留着输入框，
    而且看图的时候往往正想往另一条路上说点什么）。要"整个会话真的只有分支"，把那两行 `hidden`
    反过来即可。

三处**只是取向、等 04 拍**：字号阶（原型用 12/13/14/15 四档，`--app-font-size` 现在是 14px）、
两个把手的宽度范围（左栏 208–360、阅读列 600–1000）、以及分支图里一个节点一行是不是够了
（现在一个节点 = 一条消息 item，真实现里要不要把工具步骤也铺进去是 09 的事）。
一处**明确留缺口**：原型的拖拽不持久化——刷新就回默认宽，宽度记在哪里是 04 的问题。
另一处**明确留缺口**：原型里切分支会真的换掉第 2 轮的正文（这是为了让它可点），但真实现里换的是
会话的 `leaf` 与整段记录，属于 09 号。
