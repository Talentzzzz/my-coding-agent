# 13 原型第五轮：顶部只留标题与入口、分支页专心当"总览"

Type: prototype
Status: resolved
Blocked by: 12

## Question

用户看过第四版原型之后，把**固定头**和**分支页**又收了一遍：

> 顶部固定栏，最上面是会话标题，然后去掉 对话 分支 的选项，但是保留你右上角的当前分支选项，
> 我觉得你这个入口很好，然后点击就进入分支页；现在分支页不支持左右拖动和放大，我希望放大是用
> ctrl+滚轮调整，左右拖动就是长按鼠标，我说的拖动是画面的拖动；总览页时，每个节点只显示一小段话，
> 鼠标悬停在上面时展开完整 user 的发言；并且在分支页时，底部对话框去掉；在分支页左键可以选中某个
> 节点，然后点击一个按钮，带着选中的分支回到对话页；

要定的是五件：① 固定头里放什么（标题 + 一个入口，页签拆掉）；② 分支页的鼠标手势（Ctrl+滚轮缩放、
按住左键拖画面）；③ 一个节点默认显示多少（一小段，悬停展开整句）；④ 分支页要不要留着输入框；
⑤ 选中 → 按钮 → 带着它回对话（**重申**，不是新要求）。原型仍是 `../prototype/index.html`，
回归仍是 `node .scratch/window-polish/prototype/shoot.mjs`。

## Answer

五条都落进原型了。**这一轮把 01 的 ③ / ⑫ 里"两个页签"那半拆掉了，也把 01 的 ⑫ 里"输入框留着"那条
落地成了"不留"。**

1. **固定头只有两样东西：最上面一行是会话标题，右边是「当前分支」入口。**
   **「对话 / 分支」两个页签整块拆掉** —— 用户的原话是"去掉 对话 分支 的选项，但是保留你右上角的
   当前分支选项，我觉得你这个入口很好"。于是**进分支页只有一个门**（右上角那一块：一个分叉图标 +
   `当前分支` + 短 id + 这条走法开头那句话），**出分支页也只有一个门**（分支页里那个按钮）。
   那一块**可点、有 hover**，所以它自己就说明了"点了会去哪儿"；只有一条走法时它整块收掉（09 号那条
   照旧）。标题用的是服务端派生出来的那个（`titleOfBranch`，真实现里就是它），实测推阅读列把手
   `标题 x 311 → 311`、入口 `x 733 → 733` —— 这一行还是不跟着正文宽度动（12 号那条继续成立）。
2. **分支页的鼠标手势写死成两条，并且写在了页面上。** **Ctrl+滚轮**缩放（指针指着的那一点钉在原地，
   40%–300%；⌘ 也行），**按住左键拖画面**（哪儿都行，**压在节点卡上也拖得动**）。
   这一条是上一轮的原型没做好的地方 —— 上一轮只在空白处能拖、只能按按钮缩放，用户就说了
   "现在分支页不支持左右拖动和放大"。这一轮的实现是：`pointerdown` 记起点，位移超过 **4px** 才算
   拖动（并接管 `scrollLeft/Top`、光标变 `grabbing`），**松开时没超过 4px 才算"点了一下"**；
   所以"点选中"和"拖画面"是同一个左键，靠位移分家，不再借 `click` 事件（拖动后那一下不算点）。
   实测：Ctrl+滚轮三格 `88% → 124%`（可滚范围 `840 → 1161`）、从节点卡上按住拖 220px
   `scrollLeft 121 → 321` 且**选中项没变**。摘要行后面跟了一句手势提示（"左键点一个节点选中它 ·
   悬停看整句话 · 按住左键拖动画布 · Ctrl+滚轮放大"）—— 这页的手势不写出来没人猜得到。
3. **一个节点默认只念一小段，悬停才把整句话展开。** 默认取那句话的前 14 个字（超了补 `…`），
   悬停时换成完整的那句（CSS 在 `.short` / `.full` 之间切，且不再截断、允许换行）。
   实测一个 27 字的走法：默认 `41px` 高、显示"你：分支树能不能做成树的形状…"，悬停后 `58px` 高、
   显示整句。**展开长在卡片自己身上**（绝对定位，不挤动别的节点），所以它会盖住下面那一行的卡片 ——
   这是故意的，图是拿来看结构的。完整的那句还塞在 `title` 里兜底。
4. **分支页里没有输入框了：底部的对话框整块收掉**（含工作目录那一行与状态行），这一页只有那棵树。
   用户的原话是"并且在分支页时，底部对话框去掉"，而 01 的 ⑫ 自己就标过"输入框留着这件事可以被
   推翻"—— 现在推翻了。也就是说 **09 号第 6 条（输入框去留）的答案是"不留"**，页签那个入口一起没了，
   所以这一页是一个纯粹的"总览"。
5. **选中 → 按钮 → 带着它回对话**：流程照 12 号没动（点节点只选中、按钮的措辞从「回到对话」变成
   「切到这一条并回到对话」、连点两下等于「就它了」），这一轮只是**被用户重申了一遍**，所以它是定下来的，
   不是待定的。

6. **（补）正文列宽的尺度重定：留白砍半。** 用户看完这版又说了一句"对话宽度最宽可以再宽一点，
   离左侧栏缩小一倍"。原来正文列（阅读列）是**居中 + 固定 700px**（在 1440 的窗口里，会话列 840，
   两侧各留 70px），改成**按会话列宽算**：**默认两侧各留 35px**（正好是原来的一半）、
   **拖到最宽时两侧各留 20px**（= 列宽 − 40）、**再宽也不超过 1280px**（一行字几千像素就没法读了）。
   关键是"跟着列宽走"：窗口拉大拉小、左栏拉宽拉窄（左栏把手现在会顺手重算一次），那两条缝都还是
   同一小条，不会在宽窗口里又变成两条大沟。实测：会话列 840 → 默认 **770**（两侧各 35）、
   往右推到底 **600**（下限）、往左拖到底 **800**（两侧各 20）。**参考实现是
   `clamp(680, 列宽*0.64, 920)` + 两侧各 88px 的留白预算**（`ConversationRoot.module.css` 的
   `--dsh-chat-content-width`、`ConversationWidthControls.tsx` 的 `CONTENT_EDGE_BUDGET = 176`）——
   我们这一步是把它**故意放宽**，所以不要反过来照参考实现收窄。**这条同时是 04 号票第 1 问的答案**：
   阅读列那条把手的量程 = `600 – (列宽 − 40)`（上限 1280），默认 = `列宽 − 70`。

**留缺口照旧**：切分支在原型里仍然只换第 2 轮的正文（真实现是 09 的 ⑤）；根节点不可选（它是共同祖先）；
缩放比例不持久化；**正文宽度**在原型里也不持久化（还是 04 第 2 问的事）。

**一处我自己定的、可以被推翻**：缩放按钮（`−` / `＋` / `适应`）**留着**。用户说的是"放大是用
ctrl+滚轮调整"，但只有滚轮的话没有鼠标就没法用，而且"适应"这个动作滚轮做不出来，所以我留了这三个
按钮、把 Ctrl+滚轮当成主路径（提示写在摘要行里）。要"只留 Ctrl+滚轮"是删掉那三个 `button` 的事。
