# 04 · ADR-0008：Loop 并入 Agent

Type: task（AFK）

Blocked by: 01

## Question

（执行）在 `docs/adr/` 写 0008 号 ADR，记录：为什么删掉 Loop 对象与 loop 包、为什么全部
并入 agent.ts、放弃 vendored 对照能力的取舍（满足三条件：难逆转、后人会惊讶、真实权衡）。

## Answer

**`docs/adr/0008-loop-merged-into-agent.md`**：删掉 `Loop` 对象与 `packages/loop`——引擎并入
`agent.ts`，放弃与上游的逐文件对照。按 `docs/adr/README.md` 的四件套写（背景 / 决定 / 后果 /
不可逆性与代价），再加两节（被取代的是什么 / 没有被取代的），因为这一条**部分取代了 0001**。

理由的主线是三条，按它们出现在背景里的顺序：

1. **vendored 副本的收益早已被消耗。** 「能对着上游 diff」是当初留下 loop 的唯一理由（0001
   写成「一行都不改」），但副本已被改得面目全非——无状态化、恢复机器、`SessionRuntime`，
   合并前相对初版 +242/−22 行。对着上游 diff 现在得到的是两层改动的叠加。
2. **`Loop` 是个没有信息的对象。** `Agent` 构造它时把 `prepareRequest`、`dispatchEvent` 的
   订阅、`runtime` 槽位、两个闸门、两个队列排水钩子全递了进去——引擎的每个问题都绕回
   `Agent`，这个对象只负责原路转回。删的是这层转述，不是能力。
3. **代价写明了两条**：`agent.ts` 2043 → 2956 行（编排与引擎同处一文件，只能在文件内分区）；
   与上游分家（此后跟进 pi 的循环改动只能读、手抄、自己过类型检查）。

三条件逐条落进「不可逆性与代价」：回退要重新取上游文件并对齐五处接缝、改回 `Agent` 的构造
参数（不止一处）；后来人看到 2956 行且找不到 `Loop` 必然会问为什么；被放弃的 vendored 对照
能力有真实价值。

**连带三处落库动作**（按既有约定，不另开票）：

- `docs/adr/0001-transport-websocket-mux.md` 的 `取代者` 一行从「尚无」改为指向 0008，写明
  只取代 loop 那一半、`packages/llm` 与「不引入 plugin / MCP」不变（正文一字未改）。
- `docs/notes.md` 第一节那条「`packages/llm` 与 `packages/loop` 一行都不改 —— 保留」就地划线、
  标为「保留一半」，指向 0008。

**本票不做**：`AGENTS.md` / `architecture.md` / `README.md` 的实况同步（05 票）。
