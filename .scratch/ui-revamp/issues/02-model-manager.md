# 02 · 实现模型管理交互改造

Type: task
Status: resolved
Blocked by: 01

## Question

按确认的原型改造设置面板「模型」页（`packages/web`）：

- 去掉面板右下角的全局「保存模型」按钮。
- 「＋ 添加模型」→ 内联展开空白表单，表单右下角「取消 / 保存」。
- 已有模型行：右侧悬停显示回收站图标，点击（带一次确认）删除该行。
- 点击模型行中部 → 内联进入编辑，右下角「取消 / 保存」。
- 与 `SettingsManager`「变更写回已提供该字段的那一份」的既有合并规则对齐。

## Answer

已按原型落地（`packages/web/src/render/settings.ts` + `style.css`）：

1. **全局「保存模型」按钮已移除**。改为每次操作各自发一次整表 `PUT /api/models`：行内表单的「保存」、确认后的「删除」、添加表单的「保存」各解析出各自的目标列表整体提交。被编辑行之外的原样行不带 `apiKey` 回传，服务端按既有规则保留已存密钥——与「变更写回已提供该字段的那一份」的合并精神一致（对模型这份具体契约即「省略 apiKey 即保留原密钥」，见 `packages/server/src/controllers/sessions.ts` `updateModels`）。
2. **「＋ 添加模型」** 改为虚线占位按钮；点击内联展开一张 `BLANK_DRAFT` 空表单，右下角「取消 / 保存」，展开后自动滚入视野；添加期间按钮隐去。
3. **删除**：行右侧回收站图标悬停显现（编辑态隐藏），点击在该行下方展开一次确认条——「删除 X？此操作不可撤销。」+「删除 / 取消」（按钮顺序随原型）。
4. **编辑**：点击行中部（名称 + ref 的整行按钮）内联展开表单，右下角「取消 / 保存」。表单字段与原表单一致（名称、模型 ID、服务地址、API 密钥、上下文窗口、最大输出、推理开关、默认思考等级）。
5. **保存门槛**：名称 / 模型 ID / 服务地址未填齐时「保存」禁用（服务端本就拒绝这三者缺失的行），比原型多的一道防错，错误提示仍走面板底部 note。

实现要点：

- **单一互斥交互**：编辑、添加、删除确认三者同时只开一个，开启新的会收起旧的（比原型收紧，避免行号在删除后漂移）。
- **冻结列表**：交互打开期间持有 `frozen` 行列表快照，表单所针对的行不因服务端状态更新而漂移；期间 body 整体冻结不重绘，输入焦点不被流式帧抢走。
- **行为保持**：密钥仍只写不回显（`hasApiKey` 出占位符）；保存成功后丢弃快照、按服务端回传重绘。
- 无全局保存后，note 是失败动作唯一的回话处——已修复既有 bug（`renderBody` 会清掉 `reportNote` 刚写的提示，改为重建后再报）。

验证：`npm run check` 通过（web tsc + token 审计）；smoke：`smoke-models.ts`、`smoke-settings.ts`、`smoke-sessions.ts`、`smoke-tools.ts` 全过。code-review（standards / spec 两轴）通过，发现的三个问题（stable 注释与实现矛盾、确认条按钮顺序与原型不符、状态清空重复）已当场修复。
