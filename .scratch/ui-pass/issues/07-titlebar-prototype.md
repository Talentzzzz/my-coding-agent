# 07 标题栏布局原型

Type: prototype
Status: open
Label: feature

## Question

图2 暴露两个标题栏问题，用户要求先做原型再定：

1. 右上角窗口控制按钮（最小化/最大化/关闭）压住了分支页工具行（100% / 适应 / 回到对话）——分支工具行在标题栏正下方，与窗口按钮同高冲突。
2. 标题栏整体太贴屏幕边界。

做法：产出一个便宜的 HTML 原型（放 `prototype/`），给出 2-3 个布局方案（例如：工具行左移避开窗口按钮、标题栏加内边距、窗口按钮区留白列等），交给用户挑。原型确认后从 map 的 Not yet specified 毕业出实现 ticket。

## 原型已就绪（等用户拍板）

**产物**：`prototype/07-titlebar.html`（单文件、无依赖、无持久化；`prototype/` 下与 09 号同级的遗产区）。

**怎么开**：直接双击 `prototype/07-titlebar.html`（单文件、无依赖、无持久化；和 09 号同放在 `prototype/` 这个遗产区）。两个开关都在页面上：方案 A–D、对话/分支页、窗口宽度滑块（800–1600）、按钮保留区描边、浅/深主题；`?variant=B&pane=branch` 也可以直接写进 URL。

想在**真窗口**里量（真标题栏覆盖、真尺寸）就用外壳的 `--load`，它和 `--screenshot` 一起用：

```
npm run prototype:titlebar   # 写出 prototype/shot-A.png，真窗口真按钮区
node packages/desktop/scripts/launch.mjs --load "prototype/07-titlebar.html?variant=C&pane=branch" --screenshot prototype/shot-C-branch.png
```

`--load` 会跳过服务器启动，所以拍原型不会碰 agent home。

**四个方案**（都在同一份真实构图里：侧栏拖拽条 + 标题行 + 分支页工具行）：

| 方案 | 做法 | 实测（1280×820） |
| --- | --- | --- |
| A 现状 | 什么都不留 | 分支页被按钮压住 **3864 px²**（分支芯片 + 分支工具行），对话页 **3192 px²**（芯片右缘伸进按钮区 114px） |
| B 右侧留一条 | `.header` 让出 138px | **0 px²**；标题行可用宽 ~521px，工具行仍能放下三件套 |
| C 按钮上方留一条 | 顶部 40px 只做拖拽，标题行/工具行都从 40px 之下开始 | **0 px²**（芯片横向上仍与按钮区重叠，但垂直错开，二维不相交）；代价是垂直多花 40px |
| D 只挪按钮行 | 只加宽页边距（28px）+ 分支页收起芯片 | 对话页仍 **3080 px²**——28px 边距远远不够，138px 的按钮区不是靠缩边距能躲开的 |

原型里的读数面板是现场 `getBoundingClientRect()` 算的，不是写死的数字；"被按钮压住的总面积"只统计真正会丢的控件（分支芯片、缩放组、回到对话），不算撑满整行的容器，所以它报 0 就是真的 0。

**两个结论**：

1. 只有**留出按钮宽度本身**（B 让 138px、C 让 40px 高）才真的解决，缩边距（D）不行——按钮区 138×40 是硬占位。A→D 的实测把这一点钉死了。
2. 顺带抓到一处**现成就有的溢出**：`.branch-tools` 是 flex item，自动最小尺寸等于内容宽度，所以它比 header 的 padding box 还宽，右侧直接溢进保留区（`packages/web/src/style.css:755`）。banner 文案一长，"回到对话"就被推到按钮底下——**B 方案单独加 padding 也会漏**。实现时要给 `.branch-tools` 加 `min-width: 0`（并让它可收缩），否则保留列只是个声明。

**倾向**：C 最干净——按钮那 40px 在对话和分支两页都是空拖拽带，标题行和工具行天然不冲突，也顺手把"太贴屏幕边界"解决掉（顶部有 40px 呼吸）；代价是每页少 40px 内容高度。B 保留垂直空间，但把标题行的可用宽度压到 ~520px，芯片里的句子会更早截断。等用户拍板。

**截图**：`prototype/shot-{A,B,C,D}.png`（对话页）与 `shot-{A,B,C,D}-branch.png`（分支页）。

**顺带记一笔**：为了能在真窗口里量原型，外壳加了 `--load <url>`（不启服务器、直接加载一个页面，和 `--screenshot` 一起用）；`--load` 会让外壳跳过服务器启动，所以拍原型不会碰 agent home。
