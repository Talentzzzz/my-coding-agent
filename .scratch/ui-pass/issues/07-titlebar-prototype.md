# 07 标题栏布局原型

Type: prototype
Status: resolved
Label: feature

## Question

图2 暴露两个标题栏问题，用户要求先做原型再定：

1. 右上角窗口控制按钮（最小化/最大化/关闭）压住了分支页工具行（100% / 适应 / 回到对话）——分支工具行在标题栏正下方，与窗口按钮同高冲突。
2. 标题栏整体太贴屏幕边界。

做法：产出一个便宜的 HTML 原型（放 `prototype/`），给出 2-3 个布局方案（例如：工具行左移避开窗口按钮、标题栏加内边距、窗口按钮区留白列等），交给用户挑。原型确认后从 map 的 Not yet specified 毕业出实现 ticket。

## Answer

**用户拍板：方案 A**（参考形态），并补了两条修改：

1. **面板左上角要圆角**——参考图实测面板左缘从 y=40 的 x=290 收到 y=50 的 x=280（约 10px）。原型落在 `--dsw-radius-lg`（16px）：12px 在深色主题里只有几个像素的抗锯齿，截图读起来是直角。落地时同样用 16px。
2. **会话栏右侧不要那条线**——两栏只靠填充区分。参考图 y=300 实测：会话栏 `27,27,28` 到 x=279、面板 `21,21,23` 从 x=280 开始，中间没有分隔像素。原型里 `.sidebar` 的 `border-right` 已删。

顺带发现：`prototype/` 里那条 6px 拖拽手柄的列会露出窗口填充，圆角被它切掉——把窗口填充也设成 `--dsw-bg-sidebar` 之后接缝消失（落地时 `.side-resizer` 的静止态同理，别让它变成一条可见的缝）。

**毕业出的实现 ticket**：[12 标题栏：立一条真正的顶带](12-titlebar-band.md)。

**答案落定后的最终实测**（真窗口 1280×820，方案 A）：顶带与会话栏都是 `27,27,28`、面板 `21,21,23`；面板左缘 y+40→x261、y+44→x259（圆角）；两栏接缝 x=258/259 直接由 `27,27,28` 跳到 `21,21,23`，无分隔线；第一个可点控件 y=47（顶带底 40）；被按钮压住 0 px²。

## 第二轮：结构本来就错了（已定案，留全过程）

**第一轮被否**：我把"躲按钮"当成纯粹的间距问题，四个方案都在**标题行内部**让位（加 padding / 让出 138px 列 / 顶带下移）。用户发来一张窗口截图，指出两件事——**那一整行都要留出来**，而且**正文面板的填充与会话栏不是一个深度**。

照那张图逐像素量出来，结构是：

| y | 内容 | 填充 |
| --- | --- | --- |
| 0–40 | 整条顶带，铺满窗口宽度；页面不在里面画任何东西，三个窗口按钮住在右端 | `rgb(27,27,28)` |
| ≥ 40 | 两栏开始：会话栏（继续用同一个色）+ 对话面板 | `rgb(27,27,28)` / `rgb(21,21,23)` |

**顶带和会话栏是同一个面，面板才是那个"异类"**（参考图实测：x=8 一列 819 行 `(27,27,28)`；y=12–38 整行 `(27,27,28)`；y≥40 整行变 `(21,21,23)`）。

我们现在的 bug 正是顶带被画成了 `rgb(21,21,23)`——**面板的色**（`问题/2.png` 实测：y6–70 全是 `(21,21,23)`，x=8 一列 `(27,27,28)`）。所以按钮站在"内容"的色调上、会话栏又是另一个色，整条看起来才不像标题栏——**这不是间距问题，是那一行不该有内容 + 填充选错了色**。

### 产物与开法

`prototype/07-titlebar.html`（单文件、无依赖、无持久化）。

直接双击打开就够（顶带和三个按钮都在页面上按真实几何画好了）；想在真窗口里量（真 `titleBarOverlay`）用外壳的 `--load`：

```
npm run prototype:titlebar   # 真 Electron 窗口，写出 prototype/shot-A.png
node packages/desktop/scripts/launch.mjs --load "prototype/07-titlebar.html?variant=A&pane=branch" --screenshot prototype/shot-A-branch.png
node packages/desktop/scripts/launch.mjs --load "prototype/07-titlebar.html?variant=A" --screenshot prototype/shot-A-light.png --click "#theme"
```

`--load` 跳过服务器启动，所以拍原型不会碰 agent home。页面上：`A 参考形态` / `B 统一填充`、对话/分支页、宽度滑块、`按钮保留区描边`（把 138×40 画成红框）、`切换 浅 / 深`。读数面板现场算三处**实测填充**、页面上第一个可点控件落在 y、被按钮压住的总面积。

### 实测（真窗口 1280×820）

| | 顶带 / 会话栏 / 面板 | 第一个可点控件 y | 被按钮压住 |
| --- | --- | --- | --- |
| A 参考形态（深） | `27,27,28 / 27,27,28 / 21,21,23` | 47px（顶带底 40px） | **0** |
| A 参考形态（浅） | `245,246,247 / 245,246,247 / 255,255,255` | 47px | **0** |
| B 统一填充（深） | `27,27,28 / 27,27,28 / 27,27,28` + 一道竖分隔线 | 47px | **0** |

两个方案都是 0：**顶带里没有页面内容，按钮就压不到任何东西**。

### 落地时跟着改的（实现 ticket 的内容）

1. 把顶带从 `.header` 里**拆出去**：`.header` 现在背着标题行（`packages/web/src/style.css:648`，`padding: 0 24px` + `min-height: 52px`），顶带要变成窗口级的一条，会话栏和对话列都从它下面开始。
2. 顶带的填充用 `--dsw-bg-sidebar`（`main.cjs` 的 `titleBarOverlay.color` 要跟着它走，浅/深两套）；会话栏不变；对话面板保持 `--dsw-bg-base`——**"面板与会话栏不同深度"这条关系本身就是主题定义的一部分**（把 B 统一填充当默认会丢掉层次）。
3. 拆分后 `.header-row` 不再需要 `height: var(--desktop-titlebar)`，`-webkit-app-region: drag` 归顶带。
4. 顺带修第一轮踩到的现成溢出：`.branch-tools`（`style.css:755`）是 flex item，自动最小尺寸等于内容宽度，比 header 的 padding box 还宽、右侧溢进保留区——要给它 `min-width: 0` 并允许收缩。
5. 会话栏顶部现在 46px（`sidebar-top` 40px + `padding: 6px`），落在顶带之下没问题；第一个可点控件实测在 y=47。

**倾向**（用户已确认）：A 参考形态——深色 `27,27,28` 顶带 + `21,21,23` 面板，浅色 `245,246,247` 顶带 + `255,255,255` 面板；面板左上角 16px 圆角；两栏之间不画分隔线。B 只作备选。

## 第一轮（被否，留作证据）

四个方案都在标题行内部让位，实测（1280×820）：

| 方案 | 做法 | 实测 |
| --- | --- | --- |
| A 现状 | 什么都不留 | 分支页被压 **3864 px²**，对话页 **3192 px²**（芯片右缘伸进按钮区 114px） |
| B 右侧留一条 | `.header` 让出 138px | 0 px²；标题行可用宽 ~521px，芯片里的句子更早截断 |
| C 按钮上方留一条 | 顶部 40px 只做拖拽 | 0 px²；垂直多花 40px |
| D 只挪按钮行 | 28px 边距 + 分支页收起芯片 | 对话页仍 **3080 px²** |

当时的两个结论仍然成立，只是**没回答对问题**：① 按钮区 138×40 是硬占位，缩边距（D）躲不开；② `.branch-tools` 的 flex 溢出是现成的（见上第 4 条）。

**教训（下次做原型先量参考物）**：两轮的差别不在方案多聪明，而在第一轮全凭文字描述想结构、第二轮逐像素量了用户给的参考窗口。另外第二轮的截图第一次贴错了标签（`prototype/shot2-B.png` 里其实是 C，因为 `Start-Process` 复用了同一个 stdout 重定向文件）——改成每个变体一个唯一输出路径、并在图里核对切换器标签后才提交；第一轮那批图核对过，标签是对的。
