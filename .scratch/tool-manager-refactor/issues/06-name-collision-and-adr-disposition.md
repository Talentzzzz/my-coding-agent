Type: grilling
Status: resolved

## Question

  的「编号只增不改，新开一条取代」。

### 1. 三条路逐条裁决（含各自要动什么）

#### (a) 另起新名（`ToolCatalog` / `ToolSet`），「ToolManager」维持历史含义 —— **否决**

要动什么：四张已 `resolved` 票（02/03/04/05）的正文、map 的 Destination 与 `:38-40` 雾条、
05 §3.2 写好的 `createToolRegistry(toolDefinitions())` → `createToolManager()` 替换、
04 §4 的 `SessionServices.tools: ToolManager`、以及所有按 `ToolManager` 写下的决定记录，
全部改名；同时**照样**要新开 ADR、加四个取代者指针、逐句改 `AGENTS.md` / `architecture.md`。

四条决定性理由：

1. **定案 1 是用户拍的板，票无权推翻**。map Notes §1 写死「本图不再重开，票只许细化与执行，
   不许推翻」，Notes §2/§3 又点名「一张 Map」「执行也改道」。改名改的是 Destination 的名字，
   属于推翻而不是细化；`docs/agents/issue-tracker.md` 也只许在 `## Answer` 下追加、不动 `## Question`。
2. **改名买不到消除冲突的效果**。撞的不是字符串，是「无属性服务 / 不驻留内存」这条契约：
   换叫 `ToolCatalog`，0006 决定 3、0007 决定 1/2/6、0011 的「注入一张表」判据一样被反转，
   一样要新 ADR + 四个 `取代者` + 逐句改写。代价多一次全仓改名与四票返工，收益为零。
3. 「维持历史含义」是假的（§0）：五个单例里两个已改名/并门面、`LoopManager` 三立三废，
   那张清单今天不是实况。留一个只活在旧 ADR 里的词，反而让新读者多读四份 ADR。
4. **与 05 (a) 直接打架**：05 §3.2 已把构造工厂按 `createToolManager()` 写进改动面，
   §3.4 已把 `exerciseToolRegistry` 改成 `exerciseToolManager`（「名字随 06 的定名」）。
   06 若改名，等于把 05 的定案收账再开一次。

代价照实记：保留名字确实要让**新 ADR 专门写一段「同名反义」的消歧**，并在 `AGENTS.md` 的
`service` 词条里明写「工具域是例外」。这正是 (b) 里那两笔必做的账，不另计。

#### (b) 沿用名字 + 新 ADR + 取代者指针 + 逐句改文档 —— **选**

要动什么（全部归收账票，本票不动）：新 `0016`；四份旧 ADR 各加一行头部 `取代者` 与
共八处就地 `Superseded` 标注；`AGENTS.md` / `docs/architecture.md` 逐句改写；
`docs/adr/README.md` 清单补一行；`README.md` / `docs/notes.md` 核对（结论见 §3）。

四条决定性理由：

1. **名字是用户定案**（map Notes §1），02–05 四票与 map 全按它写；(a) 已逐条否掉。
2. **「只增不改」是仓库硬规则**（`docs/adr/README.md:41-45`），且 0007/0012/0013/0014
   已经用「头部 `取代者` + 就地 `Superseded` + 新 ADR」演示过正确做法，(c) 出局；(b)
   是唯一同时守住名字与编号规则的形状。
3. **反转的理由只该有一处**：`docs/adr/README.md:9`「三处都不重复理由——ADR 是理由唯一的家」。
   新 ADR 写「为什么明知 0007 / 0011 仍要反转」，`AGENTS.md` / `architecture.md` /
   `docs/notes.md` 只链过去；旧四份 ADR 正文保持可读，读者沿 `取代者` 链就能追到今天。
4. **代价被圈在工具域、且可写清**（§2.3 的六条边界）。不写清就会有两种误读：
   「0006/0007/0011 整份作废」或「又回到 per-session 实例」。票面推荐语点名的
   「终点是一张常驻实例表 + 全量改道，代价是重新承担对象生命周期与失效归属」必须落成正文，
   不能只写成一句口号。

#### (c) 沿用名字，但把历史 ADR 正文一并改写成新形状 —— **否决**

要动什么：直接改 `0006` / `0007` / `0011` / `0015` 的决定条目、后果与现状陈述，

   `0002` 的 `取代者` 行甚至专门写了「这份 ADR 本身若再被推翻，**不要**悄悄改它——新开一条，
   并说明反转的代价」。
2. **会切断交叉引用**：0007 决定 3/4 的 `Superseded` 标注、0011 决定 2/4/5 的「取代 0007」、
   0014 的「复活 0008 决定 1/2」、0015 的「取代 0008 决定 6」全都指着旧正文的具体决定号；
   改正文会让这些引用失去对象，`docs/notes.md` 第一节「原文一律保留、当场标注」也跟着破例。
3. **代价不可逆、收益极小**：少一条 ADR，换来一次无法还原的历史丢失；而 ADR 的门槛
   （`docs/adr/README.md:33-37`）这次三条全成立——难以逆转（要动类、装配、引擎、smoke、
   四份文档）、没有上下文会让人困惑（明知 0007/0011 仍反转）、有被放弃的选项与代价
   （(a) 改名、(c) 改史，以及重新承担生命周期）。

- **「为什么明知 0007 / 0011 仍要反转」这一问的答案骨架**（票面点名，不许省）：
  1. **终点是用户定案，不是架构推理的结果**：map Notes §1–§3 拍板「一张常驻 `Map<name, Tool>`
     持有全部实例 + 引擎全量改道 Manager」，票只许细化与执行。这是反转的唯一动因，
     不许包装成「0007 当初错了」。
  2. **代价照实背上**：重新承担**对象生命周期与失效归属**——谁建表、谁写、什么时候失效、
     一次在飞的运行看哪一份。0007 拆聚合袋、0011 收「唯一的门」并删键控缓存，
     正是为了消灭这件事；这次在工具域把它请回来，就必须由新 ADR 自己回答这四个问题。
  3. **回答那四个问题（六条边界，逐条写进*没有被取代的*）**：
     - 表里只装**进程级行为**（六个目录无关的 `Tool` 实例），不装 per-session 状态、
       不按 id 键控、没有冷/热两份、没有驱逐判据——不是 0006 A 路线的 per-session 实例；
     - 活跃名单与审批仍是**账本派生的纯数据**，`toolStateOf` / `approvalToolsOf` 四函数留会话域，
       `.json` / `.jsonl` / `tool_config` 格式一字不动（04 §5 #1–#3）；
     - 每请求的值（`workDirAbsPath`、bash 超时）仍是随 `execute` 实参走的 `ToolRunContext`，
       由本轮栈上局部携带（02 (a)）——**B 路线「现建现传、不进任何袋」对每请求值仍成立，
       被反转的只是「`Tool` 对象不驻留内存」**；
     - **单写者**：只有 Manager 自己写表，首次访问一次填满六个零参工厂，
       `register()` 只加新名字、同名（含内置）抛错、已有条目与 Map 对象不可换
