## Question

把设计对话敲定的形状落成 `docs/adr/0007`(编号顺延现库),正式**重开 ADR-0006 中
「薄壳门面」一条**(票 08/09/16 有意保留 `SessionManager`/`SettingsManager` 私有
状态袋的裁决),并记录本 effort 的形状契约:

- **无聚合袋**的理由:大对象让各 Manager 互相「补充」一个共享对象,字段的生命周期
  与属主脱钩,正是旧有状态类的问题换了规模回来;改为方法收 id、谁用谁向属主现取、
  局部变量传参。
- **类壳保留**:Manager 是 Spring 式无状态服务(构造注入、可测性靠传内存袋),
  不是被删除的函数命名空间;`private s` 一类的每会话字段是唯一要拆的东西。
- **Manager 内部键控缓存**:fill-at-open、按 id / 工作区键控、随时可从磁盘重建、
  不被传递——承接 ADR-0006 的缓存规则与前作票 16 的否决(每请求全文重放)。
- **活的一半例外**:队列、activeRun、订阅集合不能从磁盘现建,居窄键控登记处
  (归属与命名是票 03 的答案,ADR 留指针)。
- **modelState 消失**:选择随消息到达,没带就从账本派生 + `fillModel` 现算。
- 五单例一致此形状;hooks / transport / systemPrompt 构建函数是进程级不可变配置,
  留作构造注入。

ADR 只落决策与理由;AGENTS.md `## 术语` 词条与 architecture.md 持有模型一节的平移
随 06/07/08 票走。完成后 `npm run check`(文档票,应无代码改动)。

## Answer

落成 [docs/adr/0007-services-drop-instance-state.md](../../../docs/adr/0007-services-drop-instance-state.md),
标题「五个单例服务不持有实例状态——聚合袋拆除,『薄壳门面』条款重开」。
Question 列的六条契约全部入文:

- 决定 §1 无聚合袋(方法收 `(sessionId, 请求自己的参数)`、用到即现取、局部变量
  传参、内部辅助不收 id 不收袋),理由记在背景一节(聚合袋让字段生命周期与属主
  脱钩、`private` 把状态边界藏回 `this`)。
- 决定 §2 类壳保留:Spring 式无状态服务、构造注入、内存袋单测;要拆的只有
  `private s` 一类 per-session 字段。
- 决定 §3 Manager 内部键控缓存:fill-at-open、按 id / 工作区键控、可从磁盘重建、
  藏在属主内部不被传递——承接 ADR-0006 §3 缓存规则与前作票 16 的否决。
- 决定 §4 活的一半例外:窄键控登记处只装「进行中且磁盘上没有」的;归属与命名
  留指针给票 03(候选 `OpenSession`),`SessionRuntime` 窄定义不动。
- 决定 §5 modelState 消失:选择随消息到达,没带从账本派生 + `fillModel` 现算。
- 决定 §6 hooks / transport / systemPrompt 构建函数是进程级不可变配置,留作
  构造注入。
