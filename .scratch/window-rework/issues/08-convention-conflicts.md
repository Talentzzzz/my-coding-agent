# 08 与仓库既有约定冲突的两处

Type: grilling
Status: closed
Blocked by: （无）

## Question

这次改造会撞上两条**已经写下来的**约定，都不是改代码能解决的，要你拍。

### 1. 状态栏语言——与 `AGENTS.md` 明文冲突

现在底部状态行显示 `total 12.3k` / `cache 96%` / `context 42%`，鼠标悬停是整句英文
（`packages/web/src/render/statusbar.ts:51-70`，`total` / `cache` / `context` 三个词加 tooltip 全是英文）。

但根 `AGENTS.md` 的「约定」一节**明文写着**：

> 面向人的字符串按用到它的地方写：窗口文案是简体中文（只有一个 locale）……**状态行的 `total`、`cache`、
> `context` 保持英文**。

所以"把它改成中文"= **改约定**（同时改 `AGENTS.md` 那句话），不是改代码。反过来，"保持英文"= 不改任何
东西，只在改造里维持现状。

要定的：**改约定**（状态栏中文化），还是**保留英文**（并接受界面上这一处刻意的不一致）？
我倾向保留英文——它是一处刻意的技术读数，不是文案；但这一条你说了算，因为它是一句写进文档的约定。

### 2. 空状态与左栏图标的观感边界

参考图的空状态是居中的大 logo + "探索未至之境"；左栏工作区标题右侧还有两个图标（搜索 / 排序）。要定：

- (a) **空状态**换成参考图那样，还是保留现在的 sparkle + 「想做点什么？」？（现在是 `transcript.ts:293-316`
  的 `setWelcome`。）
- (b) 那几个图标**要不要真功能**？真搜索需要在客户端过滤会话列表；真排序会动 `rows.ts` 的排序规则
  （现在按 `modified` 降序，见 `sidebar.ts` 的 `rowsOf`）。还是先只做观感、点了没反应？

**01 号已经读出来了**（细节见 `../research/ui-spec.md`）：那一处源码里其实是**三个**控件——搜索 / 视图
选项 / **添加工作区**；空闲会话每组默认显示 **5** 条会话行，「展开其余 N 个会话」在**组内列表末尾**；
空状态是 34px 鱼形 logo + 「探索未至之境」(26/32, wt500) + 一个写着「预览版」的**上标徽章**——源码里
**没有独立副标题元素**，所以想要一行真正的副标题就是新增，没有对应物可抄。

于是 (b) 现在要定的是三件事：搜索要不要真过滤、视图选项要不要真排序、以及**"添加工作区"要不要做**
（注意它与 07 号已经选定的"A 只列已知工作区、不做浏览"**直接冲突**）。

**产出**：两条决定。

## Answer

**决定（2026-10-14 拍板）：**

### 1. 状态栏语言：保留英文

不改约定、不改代码，改造中维持现状（`total` / `cache` / `context` 三个词及 tooltip 均保持英文，
tooltip 整句也维持英文）。理由：状态行是一处刻意的技术读数，不是文案；`AGENTS.md` 那句话原样生效，
界面上这一处「窗口文案是中文、状态行是英文」的不一致是**有意的**，不是漏翻。

### 2. 空状态：保留现状

`transcript.ts` 的 `setWelcome` 不动——维持 sparkle + 「想做点什么？」，**不**抄参考图的
34px 鱼形 logo + 「探索未至之境」+ 「预览版」徽章。

### 3. 左栏图标：搜索真、排序观感

- **搜索**：做真功能——客户端过滤当前会话列表（不需要后端配合）。
- **视图选项（排序）**：只做观感，点击无反应；排序维持 `sidebar.ts` `rowsOf` 现状（`modified` 降序），
  **不动** `rows.ts` 的排序规则。
- **添加工作区**：**做**。点击后调起 **Windows 系统文件夹选择器**（OS 原生对话框），用户选中一个
  文件夹后把它加入工作区列表。注意这里不是应用内目录浏览，也不是手输路径——应用内仍然不列目录，
  自由路径的入口完全交给 OS 对话框。

不记忆）不受影响，维持原判。
