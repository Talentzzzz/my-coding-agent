# 0004：模式是一次工具集与审批集的选择，不是一个新状态层

日期：2026-10-17 · 状态：已接受（ui-revamp 03 号票拍板并落地）

## 背景

一次会话关于工具的两半事实——哪些工具激活、哪些要审批——已经各有一个家：

- **会话层**：一条 `tool_config` entry 持有 `(activeTools, approval)` 两份映射**整份**，由 `setActiveTools` 与 `applyConfig` 写出，读取方重放分支取最后一条；分支移动时 `applyRecordedToolConfig` 重放它。
- **全局层**：settings 文件的 `tools`（默认激活集，缺省全量）与 `approval`（默认审批映射）——是一个**新**会话打开时的默认值，也即会话级面板「沿用全局」回到的那份。

ui-revamp 03 号票要在这个之上加「模式」：一个命名的工具集合 + 每工具审批映射的预设，在全局设置里维护、在输入框左下角选择。三处候选的设计空间：

1. 模式存哪、什么形状；
2. 内置「默认」模式与既有全局默认是什么关系；
3. 会话选模式落在会话记录的哪个位置。

## 决定

1. **模式存在 settings 文件里**，是新字段 `modes`：`ModeSettings[] = { name, tools, approval }`，两份映射各自**整份**携带，与 `tools`、`hiddenWorkspaces` 同属"整表设置"——`PATCH /api/settings` 一次替换整表，没有独立的 CRUD 端点。`modes` 字段缺省即没有用户模式；旧文件不需要迁移。
2. **内置「默认」模式不被存储**。它就是全局默认的**活视图**：`settings.tools ?? 全量` 加 `settings.approval`。选「默认」= 会话回到全局默认，与会话级面板的「沿用全局」是同一件事的两种说法（该面板在 ui-fix-pass 02 已删除，见文末「后续变更」）。
3. **会话选模式不写新 entry kind，也不加会话端点**。施加一个模式 = 现有 `PUT /api/sessions/{id}/tools` 与 `PATCH /api/sessions/{id}`（`approval`）两个命令的组合，由窗口发出，落既有 `tool_config` entry——模式选择是**状态**（这个会话当时用什么工具与审批），恰好是 `tool_config` 已经记录的东西。
4. **名称是身份**（与模型行的 `name` 同一规则）：与内置「默认」或彼此重名的模式在控制器被拒绝，而不是被悄悄改名。

## 后果

换来的：

- 无迁移、无新协议成员之外的改动：`SessionSnapshot`、`config_changed`、follow-global 判断、分支重放全部原样工作——一个被施加了模式的会话，与一个早先手动勾出同样工具集与审批集的会话，在任何读取方眼里**不可区分**。
- 「默认」永远与全局默认一致，不存在第二份需要同步的拷贝。
- 会话级面板的手动微调仍然有效：选完模式再单独翻一个开关，是一次普通的 `tool_config` 变更。这条入口在 ui-fix-pass 02 已删除；改动会话那半边现在只有「选一个模式」一条路。

背上的：

- **会话不记录"它在哪个模式上"**。窗口是从快照的 `(activeTools, approvals)` 与当前模式表**按值匹配**出来的：值相等即命中。模式被改名或改内容后，旧会话的匹配会失配（显示为未命中），这与其余按名字作身份的东西（模型行）同款代价。
- 模式里的工具名是**当时**的构建给的：一个名字后来被构建丢弃的模式，施加时由窗口按 `allTools` 收窄（与 `applyRecordedToolConfig` 收窄记录集是同一条规则）。
- `modes` 的形状进了 settings 文件与 wire（`SettingsSnapshot`），改动它要同时动 core、server、web——它是一个加法字段，回退容易。

## 不可逆性与代价

低。`modes` 是纯加法字段；`tool_config` 的语义一字未动；去掉模式系统等于删掉字段与两块 UI。真正难以回头的决定只有一条：**默认模式是活视图而不是存储行**——若将来要让「默认」独立于全局默认（比如默认模式想比全局多收窄一个工具），就需要把它变成存储行并处理与既有 `tools`/`approval` 字段的关系，那是一次真正的迁移。

## 被放弃的选项

- **新 entry kind `mode_change`**：`tool_config` 已经整份持有同样的两份映射，`mode_change` 只会多一个重放分支和一种"两份记录互相对不上"的可能。放弃。
- **会话端点 `POST /api/sessions/{id}/mode`**：一个端点说两件事，而这两件事各自已有端点；「沿用全局」早已是同样的双命令组合。放弃。
- **默认模式存储一份**：需要迁移既有文件，且"存储的默认"与"全局默认字段"从此要互相同步——两份真相是这类系统最贵的负债。放弃。

## 后续变更

ui-fix-pass 02（同日）删掉了会话级设置面板：会话的工具与审批不再有手动编辑入口，选一个模式是改动它的唯一方式（老会话记录里的 `tool_config` 仍照常回放）。「默认」模式本身也改成和普通模式一样的行内表单——头部可点开，名称只读，保存写全局 `tools`/`approval`，不写 `modes` 列表。本 ADR 的核心决定（默认不存储、是活视图；会话选模式是两个既有命令的组合）未变。
