# 0018：会话存模式指针——工具配置从「值的快照」改成「名字 + 审批增量」

日期：2026-11-15 · 状态：已接受，已落地

## 背景

一个会话的工具配置有两半：哪些工具激活、哪些工具要审批。自 v5 起（ADR-0008）它整体住在 `.json`
快照的 `activeTools` 与 `approval` 两个字段里，而模式（ADR-0004）只是全局设置里的命名预设：
施加一个模式 = 窗口把预设的两份值抄进快照（`PUT /tools` + 审批 `PATCH` 的组合），读取方看快照的值，
窗口的「座位」从快照与模式表**按值匹配**出来——匹配不中显示「自定义」。

这个形态有三个代价：

1. **座位是三态的**（默认 / 具名模式 / 自定义），而 ui-fix-pass 02 删掉会话级手动编辑后，「选一个
   模式」已是改动工具配置的唯一入口——「自定义」只能因模式被事后编辑而出现，却要在协议、匹配
   逻辑与 UI 里永远占一个位置。
2. **值是决策时刻的快照**：模式的实质变更（改名、改内容）让旧会话的座位静默失配，显示为
   「自定义」，用户无法从任何地方看出会话在用什么。
3. **wire 上的冗余**：`toolsFollowGlobal` / `approvalsFollowGlobal` 两个 follow-global 标志在
   会话级面板删除后已经没有任何客户端消费方。

## 决定

1. **快照存指针，不存值**。`SessionMeta` 的 `activeTools` 让位给 `mode?: string`——settings
   `modes` 表里的一个名字；**缺席即内置「默认」**（跟随全局默认的活视图），不存在「默认」的第三种
   写法。激活集与审批基线在每次读取时经 `toolStateOf` 从指针活态解析：模式改了内容，会话跟着变；
   没有任何值副本需要失效（与模型选择的解析同构，ADR-0013 的「每次现读」）。
2. **指针悬空读作默认，指针本身保留**。指向的名字被改名或删除后，会话按全局默认运行，但快照上的
   名字不清理——模式再出生（重建或改回）时，会话重新挂上。这是指针语义的一部分，不是一次清理。
3. **会话自己的审批决定是一条增量**。`approval` 字段保留，语义从「完整映射」收窄为「会话明确动过
   的键」：grant 的「该工具不再问」（ADR-0005 §5）、审批补丁写下的键。增量叠在模式解析出的审批
   基线之上；模式与全局默认的变化都不动它——会话在这一工具上的明确决定不是模式的财产。
4. **座位是快照的字段**。`SessionSnapshot` 加 `mode?: string`（指针解析成功的名字；缺席或悬空为
   undefined，读作「默认」），删掉 `activeTools`、`approvals` 与两个 follow-global 标志。窗口从
   `currentModeName()` 的按值匹配变成直接读字段——座位两态：具名模式或「默认」。
5. **施加模式是一条命令**。`ConfigPatch` 加 `mode?: string | null`（`null` 即指回默认）；ADR-0004
   曾拒绝的会话端点不需要复活——它拒绝的理由（「一个端点说两件事」）已随值存储的消失而消失，
   指针本来就是一个值。`PUT /api/sessions/:id/tools` 与 `Agent.setActiveTools` 整体删除：工具集合
   的变更只有「选一个模式」这一条路。`config_changed` 事件丢掉 `approvals` / `tools`，带上
   `mode`（座位真的动了才发；`null` 显式携带「回到默认」，因为 JSON 丢掉 undefined）。
6. **盘上版本升到 6，不迁移**。旧快照的两份值映射没有可靠的逆映射（值对不回模式名），按本仓库
   的一贯约定（ADR-0008）版本不对的配对在打开时删除。
7. **名字是身份的规则延伸**：窗口不再需要匹配，但快照的 `mode` 字段只在名字解析成功时携带——
   悬空指针不假装还停留在已离开的预设上。

## 后果

换来的：

- 座位从三态降到两态，「自定义」连同它的按值匹配逻辑（`sameTools` / `sameApprovals`、收窄比较）
  从窗口消失。
- 模式的实质变更有了明确语义：**跟着变**。改一个模式就是改所有指向它的会话——这是拍板的选择，
  不是副作用。
- `SessionSnapshot` 少四个字段，多一个真正被读的字段；`followsGlobalOf` / `toolConfigFollowsGlobal`
  / `globalDefaultToolState` 与「字段相等还是存在记录」的判断整体退场。
- 一条 wire 命令替代两条命令的组合，`PUT /tools` 从 API 表、路由清单与 facade 守卫的面上消失。

背上的：

- **存量会话删除**。升版本即删（决定 6），用户可见的代价。
- **模式改内容会穿透旧会话**，包括聊到一半的——工具集可能在一次对话中途变化。这是指针语义的
  直证，需要时用「复制模式再改」规避。
- **grant 增量是会话对全局默认的一笔冻结**：会话 grant 过 `edit` 之后，即使全局默认不再闸
  `edit`，增量里的 `edit: false` 仍把它闸住（增量覆盖基线）。这与 grant 的语义一致（会话明确
  说过「这个工具别再问我」），但值得知道。
- 「默认」比具名模式少一层冻结：跟随全局默认*活态*，指针缺席就是它——ADR-0004 判为不可逆的
  「默认模式是活视图」这条决定未变，反而更纯粹了。

## 与其他 ADR 的关系

- **取代 ADR-0004 的决定 3**（施加模式 = 两条命令的组合写值；座位按值匹配）及其后果条款里
  「会话不记录它在哪个模式上」。决定 1（模式存 settings）、2（默认不存储，是活视图）、4（名字是
  身份）全部保留。
- **ADR-0008** 的格式版本推进到 6，沿用「不迁移、删除打不开的配对」。
- **ADR-0005 §5** 的 grant 记录选择不变，落点从整张映射收窄为增量。
- **ADR-0013** 的「每次现读、不留副本」从模型选择延伸到工具配置的解析半。

## 不可逆性与代价

低到中。快照字段的形状变了，回退需要一次真实的格式往返；其余一切（`fillTools` 的契约、settings
的 `modes` 形状、审批闸门的语义）原样工作。
