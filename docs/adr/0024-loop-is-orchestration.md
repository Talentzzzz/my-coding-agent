## 背景

同一批代码的第六次搬家，这次与前五次都不一样：0008 删对象并文件，0012 抽对象，0013 削依赖，
0014 又删对象，0022 把对象与文件分区请回来，0023 把它的依赖收成 19 动词回调面——每一次都在争论
「哪种边界划得更好」，没有一次问过「这条边界该不该存在」。0023 的判据（loop 层零 Manager 可见性）
成立、答辩完整、落地也干净；但落地次日把问题翻过来问了一遍：**这条边界守的是谁？** 答案是：守的
是 `Agent`，防的是 `Agent` 自己的引擎。判据定了新层级之后，前五次争论的对象消失了。

## 判据

**loop 不是编排旁边的一层，它就是编排。** 0022/0023 划的不是两层的边界，是同一层内部的边界；
既然两边是同一件事，任何为跨越它而付的成本都买不到东西。

### 正面回答 0023 的三层答辩

0023 在「正面回答 0022 的判据三层」一节立住了自己的边界；它的判据成立，本 ADR 不说它错，回答的
是「判据成立，然后呢」：

1. **「零 Manager 可见性」成立吗？** 成立，落地也做到了——但它是**内部**可见性，不是跨层的。
   一条边界划在 `Agent` 与 `Agent` 的引擎之间，守的是自己；可见性纪律没有错，错在它值得一条边界。
2. **0023 买到了什么真东西？** 两件：把 loop 需要什么收成一份 19 项清单（类型上一次性可见），
   以及一条可机器化的守卫。第一件随方法迁回变成 `Agent` 的私有类面，清单本身消失——读私有方法名
   就是读清单；第二件是**净损失**，如实记进「后果」，不粉饰。
3. **0008 的试金石现在指向哪？** 它问「为什么这个必须绕回编排层」。边界撤掉后，这个问题不再有
   对象——不是被回答，是被取消：引擎的每一次读取都是 `this` 上的一次直取，没有「绕回」可言。

## 决定

1. **删 `loop-manager.ts`。** 14 个成员原样成为 `Agent` 的私有方法（名字不变，九个失去首只袋
   参数；名单与签名见票 001 §A/§B）。编排与引擎重新是同一个对象。
2. **文件级机件搬到 `agent.ts` 末尾，恢复机器仍导出。** `danglingToolCallsOf` /
   `recoverPendingToolCalls` 语义只搬不改，`index.ts` 的 re-export 改指 `./agent.ts`（票 002），
   包对外名字一字不变。
3. **`LoopOptions` / `CompactOptions` / `CompactCallbacks` 与整组接缝类型删除。** 留下的三件值
   （`state` / `bag` / `start`）收成 `RunInput`——它没有依赖面（服务全在 `this` 上），不是那只袋
   的还魂；接缝类型改为在调用现场直用 `HookEvent<…>` / `HookResult<…>`，「同步点」这件事消失
   （票 002）。
4. **19 动词作为边界契约死掉。** 8 个留成私有方法（带逻辑或 ≥3 处复用；名单见票 001 §C），其余
   直调 `this.`——单行镜像就是 0023 自己否掉的那件事；直调不是越界回潮，因为没有人隔着边界。
5. **`check-loop-boundary.ts` 删除，`npm run check` 摘一条。** 守卫不是被削弱，是**没有对象可查**
   ——`loop-manager.ts` 不存在了，「引擎文件禁 import 编排层与 Manager」禁的是一条不存在的边。
6. **不再用搬文件治规模。** 下次嫌 `agent.ts` 大（实测 2928 行，见后果），另开一张图，口径是
   「一个类一件事」——拆 `Agent` 这个类，不是切文件。拆类会立刻退回一个「运行对象」，那正是 0012，
   必须是另一场独立辩论，不能顺手做。

## 后果

换来的：

- **约 170 行契约文本消失**：25 字段的 `LoopOptions`、两条 Pick 链、整组接缝类型，以及为它们写的
  答辩注释——其中一部分搬到新方法的注释上，所以文件行数不按这个数掉。一个文件、一只守卫脚本随行。
- **读「一次运行怎么开始」不再跳文件。** 编排与引擎同处一个类，`startPromptedRun` → `run` 的链在
  一个文件里读完；运行的读数与命令面的读数成为同一批 `this.` 调用，两类读数的漂移从结构上不可能。

背上的：

- **`agent.ts` 2928 行、`Agent` 类 1795 行**（终态实测，票 005 §五：类占 204–1998，机件段约 915 行；
  票 001 §F 的 2820/2450 是落地中途的实测，类的数字与该节自己的 2820 对不上，以终态为准）。
  0008 那句「没有第二个文件
  可以指」原样回来——这次是有意买回，规模问题不再用搬文件治（决定 6）。
- **边界审计的机器可见性丢了。** 0022/0023 的守卫能把「引擎越界」变成机器事实；合并后没有这条边，
  审计退回人工。这是这次唯一的净损失。

## 尚未决定

`Agent` 是否该按「命令面 / 一次运行」拆成两个协作对象。**不在本图内**，且明确写出：拆它会重新
引入一个「运行对象」——那正是 0012，需要独立论证，不能顺手做。在那之前，`agent.ts` 的规模是
这次决定的已知代价，不是待办。

## 不可逆性与代价

三条门槛逐条成立：

- **难逆转。** 回去要把 14 个成员重拆回对象、把 19 动词的答辩与袋重新装配、把守卫的负向禁令
  重建——不止一处，不止一个文件，每一步都有 ADR 在案。这条链本身要求每次转向都写下「为什么这次
  不一样」，本 ADR 的回答是：判据换了层级——不再是「哪种边界划得更好」，是「这条边界该不该存在」。
- **没有上下文会让人困惑。** 0023 的判据成立、答辩完整、落地干净，一天后却被整体取代——没有
  「判据成立但买不到东西」这条主线，第一反应必然是「白名单原则又被推翻了」。区别不是原则错了，
  是原则所守的边界本身是假的。
- **是真实取舍。** 被放弃的选项各有代价：维持 0023 就继续为一条内部边界付组袋与闭包接线的税；
  「只删袋不删文件」会留下一只守不了自己、却还占着文件分区理由的对象，比现在更糟。

## 被取代的是什么

逐条对照 [0023](0023-loop-manager-functions-only.md)（其「背景」的三层答辩不再复述，判据节各以
一句话回答）；0022 由 0023 延续的部分随 0023 一并取代：

- **决定 1**（袋上无 Manager）：边界死了，袋与「零 Manager 可见性」一并作废——引擎不再隔任何
  东西。
- **决定 2**（回调粒度是语义分组）：作为契约作废；分组的成果保留为方法边界——8 个有语义的留成
  私有方法，其余直调。
- **决定 3**（`bagOf` 退出白名单）：开袋路径仍只剩 `recordSelection` 内部一处——这条成果以私有
  方法的形式活下来，只是不再需要白名单来守。
- **决定 4**（`servicesOf` 组装点消除）：继续成立，更彻底——组装点连同回调一起消失，fanout 直调。
- **决定 5**（`executeTool` 镜像 0016）：0016 不动照旧；「镜像」这个目的随边界消失，`executeTool` 留成
  私有方法是执行链的复用，不是隔表纪律。
- **决定 6**（hooks 三动词）：三个闸门仍是三个私有方法，事件与答案类型直用 `HookEvent<…>` /
  `HookResult<…>`（票 002）。
- **决定 7**（守卫收紧）：作废，见决定 5。
- **决定 8**（出口口径）：出口名字不变，住址改到 `./agent.ts`（票 002）。
- **判据节的 `LoopOptions` 完整形状与 `CompactOptions` Pick 链**：作废；仍被消费的类型
  （`ActiveTools` 等）迁进 `agent.ts`（票 002）。「不进袋」清单——模型、abort controller、
  transport、`thinkingLevel` 全是运行局部量——逐字继承。

## 没有被取代的

明确不动、读者不该跟着本 ADR 一起重开的：

- **0019 的 bag 语义**：一次运行读一次盘、`live.unwritten` 只活在表上；开袋路径仍只有
  `recordSelection` 一处。
- **0023 落地的更硬不变量**：工具调用只能解析到本请求声明过的工具（对 `context.tools` 按名查）
  ——这条与边界无关，原样保留。
- **0016 的工具实例表、0017 的消费边界**：`ToolManager.execute` 仍是生产唯一入口，Manager 的唯一
  消费者仍是编排层——现在 loop 也是编排的一部分，这条边界的陈述反而更简单。
- **0006 §5 的结束重启审批**：恢复机器语义一字不改，只是住址换了；`smoke-approval-recovery`
  照旧直驱。
- **0021 的 `suspended` 显示标记、0003 的取走点落盘、0007 的无属性服务、fanout 文件与参数形状、
  abort / settle / close 不进运行机械、命令面 REST + 常驻 mux、订阅与 hold 分离、不重开 pi-ai
  上游对照（0008 决定 9）**：一律不动。
