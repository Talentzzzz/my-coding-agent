# 0020：工具名清单离开快照——编排层窄读 + `GET /api/tools`

日期：2026-11-15 · 状态：已接受，已落地

## 背景

`SessionSnapshot` 曾带一个 `allTools: string[]` 字段：本构建注册的每个工具名，按注册顺序。它
是 `ToolManager` 注册表的名字清单（ADR-0011），但被搭在**会话快照**上——客户端要渲染模式菜单
里内置「默认」行的摘要、设置面板的工具清单，并给落盘的工具名做落地过滤，而客户端摸不到注册
表，这份名单就必须走在某条协议消息上。

问题在于它不是会话状态：它对每个会话都一样、进程活着就不过期。会话快照的合同是「这个会话此刻
的状态」，一个进程级事实放进去，每次投影都在重复搬运一个不随会话变的东西。

## 决定

1. **`SessionSnapshot` 不再携带工具名清单**（`SnapshotInput` 同步删字段）。快照回到纯会话状态。
2. **编排层开一个窄读**：`Agent.toolNames(): string[]` → `this.tools.names()`，与 `titleOf` /
   `holdsOf` 同类——ADR-0012 的「窄状态读…返回纯数据」。server 不许碰 `ToolManager`（ADR-0012），
   所以通往注册表的路只有这条。
3. **一条 REST 端点作答**：`GET /api/tools` → `{ tools: [...] }`，`SystemController.toolNames()`
   转手编排层。落在「加一个端点 = 控制器上一个方法 + `createRoutes()` 一条记录」的既定形状里。
4. **客户端启动时取一次**：`SessionApi.toolNames()` 在启动 IIFE 里与 `getSettings` 并排拉取，
   存进 `ViewState.toolNames`，模式菜单与设置面板都从这份读。清单是静态的（六个内置，
   `register()` 只给测试），所以一次拉取后无需任何失效机制；应答前的一瞬以六个内置兜底。

## 后果

- 快照合同更纯：不再有「不随会话变」的字段。冷读（`readSessionSnapshot`）与活跃投影不再各自
  填一遍注册表。
- 设置面板的 `standDown` 逻辑整个删除：原来「没有会话就没有名字清单，内置默认的表单退下」的
  前提消失了——名字清单不再依赖会话，内置默认随时可编辑、可保存。
- 客户端多一次启动请求、少一份随帧重复的数据。两边平衡。
- 模式菜单、设置面板的收窄与兜底语义不变：名字清单从快照换成启动拉取的那份（ADR-0004 的施加
  时收窄读的是同一份事实）。
